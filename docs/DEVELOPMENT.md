# Development notes

How the code is laid out, how to build and test it, and how releases reach phones.
For what the app does, see the [README](../README.md).

## Project layout

```text
lib/
  main.dart, app.dart        app start, onboarding, lock screen, bottom tabs
  providers.dart             Riverpod providers (database, ledger, live queries)
  data/
    database.dart            Drift tables and migrations (schemaVersion 4)
    database.g.dart          generated by build_runner (committed; CI fails if it is stale)
    encryption.dart          database encryption: key format, in-place encryption, decrypted backup copies
    database_key.dart        loads or creates the key at startup; handles a lost key without deleting data
    seed.dart                default categories and settings on first launch
  domain/
    ledger.dart              double-entry ledger: entries, postings, budgets, summaries
    money.dart               amounts in minor units (cents) and formatting
    backup.dart              zip backup / restore, optional AES password
    update.dart              in-app update from GitHub Releases
    app_spending.dart        spending per app (Google Play / Takeout)
    place_spending.dart      spending per shop or place (Taobao shops, merchants)
    app_icon_lookup.dart     finds app icons on Google Play / the App Store
    xlsx.dart                minimal .xlsx reader (Taobao 导出订单 files)
    capture/
      capture_service.dart   turns notifications / emails / imports into 待確認 items
      parser.dart            rule-based parsing of amounts and merchants
      gemini.dart            optional Gemini fallback (unrecognised text, screenshots)
      sources.dart           notification bridge, Octopus NFC, Gmail Apps Script
      takeout.dart           Google Takeout Play purchase history
      taobao.dart            Taobao Excel / JSON orders, CNY→HKD daily rates
  ui/                        one file per screen, theme.dart for colours and shared widgets
android/app/src/main/kotlin/hk/mario/money_manager/
  PaymentNotificationListener.kt  reads notifications from allowed apps
  CaptureStore.kt            queue the Dart side drains when the app opens
  OctopusReader.kt           reads the Octopus card balance over NFC
  AppIcons.kt                icons of installed apps
  MainActivity.kt            method channels, install permission, FLAG_SECURE
test/                        unit and widget tests (run in CI)
tool/screenshots/            README screenshot generator (not run in CI)
tools/setup-android-signing.ps1  one-time creation of the release signing key
```

Money is stored as integers in minor units. Every record is a journal entry with postings that sum to zero:
- expense: fund account → category;
- income: category → fund account;
- transfer: fund → fund.

## Build and test

```bash
flutter pub get
dart run build_runner build --delete-conflicting-outputs   # after changing Drift tables
flutter analyze
flutter test
flutter run
```

Drift stores `DateTime` values as text (see [build.yaml](../build.yaml)). When you change a table, bump `schemaVersion` and add a migration step in `database.dart`. Then save the new schema and regenerate the helpers, so [test/migration_test.dart](../test/migration_test.dart) checks the upgrade from every earlier version:

```bash
dart run drift_dev schema dump lib/data/database.dart drift_schemas/drift_schema_vN.json
dart run drift_dev schema generate drift_schemas/ test/generated_migrations/
```

For data changes in a migration, add a test like [test/migration_v3_test.dart](../test/migration_v3_test.dart).

### Database encryption

`pubspec.yaml` selects SQLite3 Multiple Ciphers (`hooks: user_defines: sqlite3: source: sqlite3mc`). At startup `main.dart` loads a random 256-bit key from `flutter_secure_storage` (or creates one) and every connection runs `PRAGMA hexkey`. A plaintext database (from an older version or a restored backup, which is always plaintext so it restores on any phone) is encrypted in place before it is opened. If the database is encrypted but the key is gone, the app shows a screen that can set the unreadable file aside (renamed, not deleted) and start a new one. See [test/encryption_test.dart](../test/encryption_test.dart).

## Screenshots

The README images in [docs/screenshots/](screenshots/) are rendered by a widget test from made-up demo data:

```bash
flutter test tool/screenshots --update-goldens
```

It needs a font with Chinese glyphs. It looks for Noto Sans HK/TC on Windows, Noto Sans CJK on Linux and PingFang on macOS. Set `SCREENSHOT_FONT=/path/to/font.ttf` to use another one. Dates are relative to today, so the numbers change each time you regenerate.

## CI and releases

[.github/workflows/ci.yml](../.github/workflows/ci.yml) runs on every pull request and on every push to `main`. It has two jobs:

1. **test:** checks the committed generated code is current, then `flutter analyze` and `flutter test`.
2. **android:** builds a release APK signed with the permanent key. The build number is the workflow run number.
   - On pull requests, it is uploaded as a workflow artifact.
   - On `main`, when `version:` in `pubspec.yaml` has not been released yet, it is published as GitHub release `build-N` titled `vX.Y.Z (build N)` with an `.apk` asset. To ship a new version, raise `version:`.

Runs on `main` are queued one at a time, so releases appear in build order.

In the app, **設定 › 檢查更新** reads the latest releases of this repo and picks the highest build number. It downloads the APK, checks its size and SHA-256, and hands it to Android's installer. Because every build is signed with the same key, it installs over the old version and keeps the data.

### Signing key

The release key is created once with `tools/setup-android-signing.ps1`. The script stores it as GitHub Actions secrets:

| Secret | Content |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | the `.jks` keystore, base64 |
| `ANDROID_KEYSTORE_PASSWORD` | keystore and key password |
| `ANDROID_KEY_ALIAS` | key alias |

> [!CAUTION]
> Don't run the script again once releases exist. A new key means new APKs can't update the installed app; users would have to uninstall it and lose their data. Keep the folder the script prints in a safe place.

Without `android/key.properties`, local release builds use the debug key (see [android/app/build.gradle.kts](../android/app/build.gradle.kts)).

## Adding a payment source

1. If the app posts a notification, add its package name to `knownSources` in `lib/domain/capture/parser.dart`. Any app can still be allowed by hand in the settings.
2. Add parsing rules to `parser.dart` and a test in [test/capture_test.dart](../test/capture_test.dart) with **made-up** notification text.
3. Anything the rules can't read goes to Gemini, if the user has set a key.

## Platform notes

- Android only in practice. An `ios/` project exists, but these features check `Platform.isAndroid` and do nothing elsewhere:
  - notification capture;
  - Octopus NFC;
  - in-app updates.

  CI does not build iOS.
- Gemini's API is not available in some regions (for example Hong Kong). The app shows the API error, and the rule-based parser still works without it.
- `android:allowBackup` is off. Users move data with the app's own backup (設定 › 匯出備份).
